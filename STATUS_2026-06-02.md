## 1. О проекте

Atom — это язык программирования для написания нейросетей, сочетающий простоту Python и скорость C. Проект включает собственный компилятор с WebAssembly бэкендом, нацеленный на self-hosting (компилятор, написанный на самом Atom).

### Ключевые цели

1. Написание современных нейросетей
2. Собственная IDE для Atom
3. Собственная LLM на Atom
4. ИИ-агент уровня Claude Code на Atom

## 3. Что уже работает

### 3.1. Лексер на Python (`lexer.py`)
- Разбивает код на токены
- Поддерживает отступы (INDENT/DEDENT)
- Распознаёт числа, операторы, идентификаторы, ключевые слова

### 3.2. Лексер на Atom (`lexer.atom`)
- Полностью написан на языке Atom
- Компилируется в `output.wasm`
- Распознаёт: числа, операторы (`+`, `-`, `*`, `/`, `=`, `<`, `>`, `:`), идентификаторы
- Возвращает `TOKEN_EOF` в конце файла
- **Используется как основа для всего компилятора**

### 3.3. Компилятор на JavaScript (`advanced_compile.js` и др.)
- Использует скомпилированный лексер (`output.wasm`)
- Поддерживает:
  - Переменные и присваивания (`x = 42`)
  - Арифметические операции (`+`, `*`)
  - Многострочные программы
  - Вычисление выражений
  - Генерацию WebAssembly кода

### 3.4. WebAssembly генерация
- Создаёт `.wat` текст из AST
- Компилирует в `.wasm` через `wat2wasm`
- Выполняет скомпилированный код через Node.js

## 5. Текущие ограничения

| Ограничение | Статус | Приоритет |
|-------------|--------|-----------|
| Ключевые слова (`if`, `else`, `while`) | ❌ Не работают | Средний |
| Имена переменных не сохраняются | ❌ Используются временные имена | Средний |
| Парсер на Atom не компилируется | ❌ Требует доработки Python парсера | Высокий |
| Поддержка вычитания и деления | ⚠️ Частично | Низкий |
| Приоритет операторов | ⚠️ Только слева направо | Низкий |

9. Известные проблемы и решения
Проблема: Python парсер не понимает синтаксис функций в Atom
Решение: Временно используем JavaScript компилятор. Позже доработаем Python парсер.

Проблема: Лексер не возвращает EOF после NEWLINE
Решение: В компиляторе читаем ровно столько токенов, сколько нужно, не ожидая EOF.

Проблема: Имена переменных теряются
Решение: Временно используем отображение ptr → var0, var1.... Позже добавим строки.

10. Решение об LLVM (отложено)
LLVM может упростить генерацию кода, но принято решение:

Продолжить с собственным генератором Wasm

LLVM добавить позже как опциональный бэкенд

Причина: образовательная ценность и контроль над кодом
