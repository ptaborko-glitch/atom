## 1. О проекте

Atom — это язык программирования для написания нейросетей, сочетающий простоту Python и скорость C. Проект включает собственный компилятор с WebAssembly бэкендом, нацеленный на self-hosting (компилятор, написанный на самом Atom).

### Ключевые цели

1. Написание современных нейросетей
2. Собственная IDE для Atom
3. Собственная LLM на Atom
4. ИИ-агент уровня Claude Code на Atom

## 3. Что уже работает

### 3.1. Лексер на Python (`lexer.py`)
- Разбивает код на токены
- Поддерживает отступы (INDENT/DEDENT)
- Распознаёт числа, операторы, идентификаторы, ключевые слова

### 3.2. Лексер на Atom (`lexer.atom`)
- Полностью написан на языке Atom
- Компилируется в `output.wasm`
- Распознаёт: числа, операторы (`+`, `-`, `*`, `/`, `=`, `<`, `>`, `:`), идентификаторы
- Возвращает `TOKEN_EOF` в конце файла
- **Используется как основа для всего компилятора**

### 3.3. Компилятор на JavaScript
- Использует скомпилированный лексер (`output.wasm`)
- Поддерживает:
  - Переменные и присваивания (`x = 42`)
  - Арифметические операции (`+`, `-`, `*`, `/`)
  - Многострочные программы
  - Вычисление выражений
  - Генерацию WebAssembly кода
- Умеет читать `.atom` файлы и компилировать их

### 3.4. WebAssembly генерация
- Создаёт `.wat` текст из AST
- Компилирует в `.wasm` через `wat2wasm`
- Выполняет скомпилированный код через Node.js

## 5. Текущие проблемы и ограничения

### 5.1. Функции без аргументов
**Проблема:** Язык Atom поддерживает только функции без аргументов:
```python
func my_func:
    x = 42
    return x
Почему так: Python парсер (прототип) не может корректно обработать синтаксис функций с аргументами вида func name(a, b):. Попытка добавить поддержку привела к нарушению отступов и синтаксическим ошибкам.

Что нужно исправить: При переходе на self-hosting или при доработке Python парсера добавить поддержку аргументов.

Приоритет: Средний

5.2. Ключевые слова не распознаются
Проблема: if, else, while, return не распознаются как ключевые слова

Причина: Лексер не имеет таблицы ключевых слов

Что нужно исправить: Добавить в lexer.atom функцию lexer_is_keyword и таблицу ключевых слов

Приоритет: Средний

5.3. Имена переменных не сохраняются
Проблема: В AST имена переменных отображаются как var0, var1 вместо реальных имён

Причина: lexer_token_value для идентификаторов содержит указатель, а не строку

Что нужно исправить: Реализовать сохранение строк в памяти Wasm

Приоритет: Средний

5.4. Парсер на Atom не компилируется
Проблема: parser.atom не может быть скомпилирован через Python компилятор

Причина: Python парсер не понимает синтаксис функций в Atom (ожидает func name: тело, а встречает func name(): тело)

Решение: Использовать JavaScript компилятор для компиляции parser.atom

Приоритет: Высокий (но отложен до завершения JS компилятора)

5.5. Приоритет операторов
Проблема: Операторы выполняются слева направо без приоритета (2+3*4 = 20, а должно быть 14)

Что нужно исправить: Реализовать правильный приоритет в парсере

Приоритет: Низкий

10. Важные замечания
Не запускайте main_debug2.py без необходимости!
Он перекомпилирует lexer.atom в output.wasm

Текущий output.wasm работает стабильно

Это временное ограничение. В будущем, когда мы перейдём на self-hosting, обязательно добавим поддержку аргументов. Пока используем глобальные переменные для передачи данных между функциями.
