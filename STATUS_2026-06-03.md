## 2. Архитектура и подход к разработке

### 2.1. Проблема "курица или яйцо"

Чтобы написать компилятор на Atom, нужен компилятор на Atom. Это классическая проблема bootstrap.

### 2.2. Решение: многоступенчатый bootstrap
Python компилятор (прототип)
↓
компилирует
↓
lexer.atom → output.wasm (работает!)
↓
используется в
↓
JavaScript компилятор (пишем сейчас)
↓
компилирует
↓
parser.atom → parser.wasm
↓
используется в
↓
hir.atom → hir.wasm
↓
используется в
↓
codegen.atom → codegen.wasm
↓
вместе дают
↓
ПОЛНЫЙ КОМПИЛЯТОР НА ATOM
↓
который может
↓
скомпилировать СЕБЯ (bootstrap)

### 2.3. Роль каждого компилятора

| Компилятор | Статус | Роль | Судьба |
|------------|--------|------|--------|
| Python | ✅ Готов (прототип) | Скомпилировал lexer.atom | Архив (история) |
| JavaScript | 🔄 В разработке | Скомпилирует parser.atom, hir.atom, codegen.atom | Временный (будет заменён) |
| Atom | ⏳ Цель | Полный self-hosting компилятор | Навсегда (финальный продукт) |

## 3. Текущий статус компонентов

### 3.1. Лексер на Atom (`lexer.atom`)
- ✅ **Статус:** Полностью готов, работает стабильно
- ✅ Распознаёт: числа, операторы, идентификаторы
- ✅ Возвращает корректные токены
- ⚠️ **Ограничение:** Не сохраняет строковые значения идентификаторов (возвращает указатели)

- 🔄 **Статус:** Написан, ждёт компиляции

- ⚠️ **Ограничения:** Временное решение, не для production

### 3.4. Python компилятор
- 📦 **Статус:** Архив, больше не развивается
- ✅ **Роль:** Историческая (скомпилировал первый лексер)

## 4. Незавершённые проблемы (требуют исправления)

### 4.1. Сохранение строк в лексере
**Симптом:** Имена переменных не читаются, лексер возвращает указатели вместо строк
**Причина:** `lexer_token_value` не содержит строку
**Решение:** Исправить `lexer.atom` (требует перекомпиляции)
**Приоритет:** 🔴 Высокий (блокирует переменные)

### 4.2. Ключевые слова (`if`, `else`, `while`)
**Симптом:** Не распознаются
**Причина:** Нет таблицы ключевых слов в лексере
**Решение:** Добавить `lexer_is_keyword` и таблицу
**Приоритет:** 🟡 Средний

### 4.3. Функции с аргументами
**Симптом:** `func name(a, b):` не парсится
**Причина:** Python парсер не поддерживает синтаксис
**Решение:** Исправить парсер или дождаться self-hosting
**Приоритет:** 🟡 Средний

### 4.4. Полноценный парсер на Atom
**Симптом:** `parser.atom` не скомпилирован
**Причина:** Нужен работающий JavaScript компилятор
**Решение:** Завершить JavaScript компилятор и скомпилировать
**Приоритет:** 🔴 Высокий (следующий шаг)

### 4.5. Приоритет операторов (полный)
**Симптом:** Частично реализован, но не для всех операций
**Решение:** Расширить парсер в JavaScript компиляторе
**Приоритет:** 🟢 Низкий (есть временное решение)

## 7. Решения и компромиссы

### 7.1. Почему не исправляем Python компилятор?
- Он не понимает синтаксис функций в Atom
- Исправление потребует переписывания парсера
- Проще написать новый компилятор на JavaScript

### 7.2. Почему JavaScript компилятор временный?
- Он не написан на Atom
- Для production нужен self-hosting компилятор
- После bootstrap он будет заменён

### 7.3. Что значит "качество продукта"?
- Нет временных решений
- Каждый компонент документирован
- Код проходит тестирование
- Проблемы фиксируются, а не откладываются
