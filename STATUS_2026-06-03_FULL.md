Чтобы написать компилятор на Atom, нужен компилятор на Atom. Это классическая проблема bootstrap.

| Компилятор | Статус | Роль | Судьба |

## 3. Текущий статус компонентов

### 3.1. Лексер на Atom (`lexer.atom`)
- 🔒 **Статус:** ЗАМОРОЖЕН
- ✅ Распознаёт: числа, операторы, идентификаторы
- ✅ Возвращает корректные токены
- ✅ Используется в JavaScript компиляторе
- ⚠️ **Ограничение:** Не сохраняет строковые значения идентификаторов

- 🔄 **Статус:** Написан, ждёт компиляции

- ✅ **Поддерживает:** Приоритет операторов, скобки, переменные
- ⚠️ **Ограничения:** Временное решение, не для production

### 3.4. Python компилятор
- 📦 **Статус:** Архив, больше не развивается
- ✅ **Роль:** Историческая (скомпилировал первый лексер)

## 4. Проблемы и решения

### 4.1. Проблема: Сохранение строк в лексере
**Симптом:** Имена переменных не читаются, `lexer_token_value` возвращает указатель
**Причина:** `string_substring` не вызывается или возвращает некорректный указатель
**Решение:** ЗАМОРОЗИТЬ лексер, использовать существующий рабочий `output_working.wasm`
**Приоритет:** 🔴 Высокий (решено заморозкой)

### 4.2. Проблема: Ключевые слова (`if`, `else`, `while`)
**Симптом:** Не распознаются
**Причина:** Нет таблицы ключевых слов в лексере
**Решение:** Отложено до self-hosting
**Приоритет:** 🟡 Средний

### 4.3. Проблема: Функции с аргументами
**Симптом:** `func name(a, b):` не парсится
**Причина:** Python парсер не поддерживает синтаксис
**Решение:** Исправить парсер или дождаться self-hosting
**Приоритет:** 🟡 Средний

### 4.4. Проблема: Ошибки типов в `wasm_gen.py`
**Симптом:** `type mismatch in global.set, expected [f64] but got [i32]`
**Причина:** Смешение типов `f64` и `i32` в сгенерированном коде
**Решение:** Используем рабочий `output_working.wasm`, не перекомпилируем лексер
**Приоритет:** 🔴 Высокий (решено заморозкой)

## 5. Стратегическое решение (3 июня 2026)

### Проблема
Python компилятор не может скомпилировать `lexer.atom` из-за:
- Синтаксических ошибок в парсере
- Проблем с типами в генераторе Wasm
- Бесконечного цикла отладки

### Решение
**Замораживаем `lexer.atom` и используем существующий `output_working.wasm`.**

Этот лексер:
- ✅ Корректно возвращает все токены
- ✅ Работает с JavaScript компилятором
- ✅ Протестирован на сложных выражениях (`2 * (3 + 4) = 14`)

### Новый план
1. Не трогаем `lexer.atom` и `output_working.wasm`
2. Завершаем JavaScript компилятор
3. Пишем `hir.js` и `codegen.js` на JavaScript
4. Получаем полностью рабочий компилятор
5. На его основе создаём self-hosting версию

### Урок
Иногда важнее двигаться вперёд, чем бесконечно отлаживать один компонент.
Рабочий прототип лучше идеального, но несуществующего.
