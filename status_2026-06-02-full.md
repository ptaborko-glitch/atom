## 1. Цели проекта

Создать язык программирования Atom для:
1. Написания современных нейросетей (простота Python + скорость C)
2. Собственной IDE для Atom
3. Собственной LLM на Atom
4. ИИ-агента уровня Claude Code на Atom

---

## 2. Архитектура компилятора
Исходный код (.atom) → Лексер → Парсер → Семанализатор → HIR → Wasm Generator → .wat → .wasm → Запуск

text

**Компоненты:**
- **Лексер** — разбивает текст на токены
- **Парсер** — строит AST (Abstract Syntax Tree)
- **Семантический анализатор** — проверяет типы
- **HIR Builder** — создаёт промежуточное представление
- **Wasm Generator** — генерирует WebAssembly (.wat)
- **Рантайм** — поддержка строк, списков, тензоров, нейросетей

5. Известные проблемы и ограничения
5.1. Ключевые слова не распознаются
Симптом: if возвращает TOKEN_IDENT вместо TOKEN_KW_IF
Причина: Сложность работы со строками в WebAssembly
Статус: Отложено, приоритет не высокий

5.2. Имена переменных не сохраняются
Симптом: В AST имена переменных пустые
Причина: lexer_token_value не содержит строковое значение
Статус: Требует исправления

5.3. Парсер на Atom не компилируется
Симптом: Python парсер не понимает синтаксис функций в parser.atom
Причина: Python парсер ожидает func name: тело, а встречает func name(args): тело
Статус: Требует доработки Python парсера

5.4. Генератор Wasm поддерживает только числа
Симптом: Нет поддержки переменных, функций, условий
Причина: Необходимо расширять парсер и генератор
Статус: Планируется

9. Ключевые уроки
Отладка br_if — в WebAssembly переход происходит, если значение не ноль, а в HIR условие было истинным. Нужно инвертировать.

Пустые строки — не должны влиять на отступы, иначе преждевременный DEDENT.

Глобальные переменные в Wasm — не экспортируются по умолчанию, нужно явно добавлять (export ...).

Работа со строками в Wasm — сложная, требует ручного управления памятью.

Bootstrap — временный парсер на JavaScript позволяет быстро прототипировать, а потом переписать на Atom.

11. Решение использовать LLVM (отложено)
Когда узнали: 2 июня 2026

Что такое LLVM: Инфраструктура для компиляции, которая берёт промежуточное представление (IR) и генерирует машинный код для разных платформ (x86, ARM, WebAssembly и др.)

Почему НЕ используем сейчас:

Мы уже почти сделали свой генератор

LLVM — большая зависимость (сотни МБ)

WebAssembly — наша единственная цель

Образовательная цель: написать генератор самим — ценный опыт

Решение: Продолжаем с нашим генератором. LLVM добавим позже как опциональный бэкенд.

Статус: Зеленая активная разработка, первый рабочий компилятор создан
